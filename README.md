# 人才补贴与职称管理系统

> Talent Subsidy & Professional Title Management System
>
> 面向 HR / 人才管理场景的一体化台账系统：把散落在 Excel 里的职称、人才账号、政府补贴申领与发放记录，
> 收敛成一套结构化、可追溯、带 AI 能力的内部系统。

**技术栈**：Vue 3 + Vite + Element Plus · FastAPI + SQLAlchemy + SQLite · ECharts · 本地大模型（OpenAI 兼容接口）

---

## 一、解决什么问题

人才补贴管理有四个典型痛点：

| 痛点 | 系统解法 |
| --- | --- |
| 数据散落在多份 Excel，口径不一、易出错 | 统一数据模型（职称 / 账号 / 政策 / 申领 / 发放五级关联），Excel 批量导入导出双向打通 |
| 补贴分期发放、跨年度，人工难以追踪每笔到账 | 按政策规则自动生成发放计划，逐笔登记与确认，自动回算「累计到账」 |
| 政策文件是 PDF/扫描件，条款靠人工记忆和翻找 | 上传政策文档 → 自动抽取原文 → 大模型解析成结构化规则 → 支持人工订正 |
| 查数据要写 SQL 或求工程师 | 内置 AI 助手，自然语言提问直接返回结论 + 中文表格，**不暴露任何 SQL** |

## 二、核心功能

### 1. 职称台账
- 工程系列（员级 → 正高级工程师）与技师系列（三级 → 一级）双体系
- 证书扫描件归档、按姓名/等级/专业多维筛选
- 记录「下一阶段申请」计划，辅助晋升规划

### 2. 人才账号
- 银行卡号、数字人民币账号 **AES 字段级加密存储**，列表仅展示 `6222***********6433` 脱敏形式
- 需要时才解密查看明文，且留审计日志

### 3. 补贴政策与 AI 规则解析
- 上传 PDF / Word 政策文件 → 自动抽取正文
- 调用本地大模型解析出结构化规则（发放周期、补贴标准、适用对象、享受期限…），每条规则可回溯到**原文引用**
- AI 结果必须经人工确认才生效；人工增删改规则后自动退回「待确认」，避免误用

### 4. 补贴申领与发放确认
- 申领台账（政策 / 人员 / BU / 应发总额 / 累计到账 / 状态）
- 按政策规则**一键生成分期发放计划**
- 发放流程：`待导入 → 待确认 → 已确认 / 有异议 → 已发放`，逐笔留批注，形成协作留痕
- 每次发放变动自动重算申领的「累计到账」，保证对账口径一致

### 5. 数据可视化大屏
- 6 张 KPI 卡片 + 6 个 ECharts 图表（年度趋势、政策占比、BU 分布、个人 TOP、职称分布、学历分布）
- 支持按年份筛选，图表实例复用避免内存泄漏

### 6. 汇报材料导出
- 一键导出 **PPT / PDF / HTML** 汇报材料
- PPT 套用公司模板（python-pptx 复用母版 + 追加原生图表），PDF 解决中文字体注册，HTML 内联样式可直接分享

### 7. AI 对话助手
- 意图路由：区分「查数据 / 改数据 / 咨询」
- 查数据走 NL2SQL：**自然语言回答 + 中文表头结果表**，不展示 SQL
- 改数据先生成执行计划，前端确认后才落地，兼顾自由度与安全
- 支持多模态：上传图片走视觉理解，上传 PDF/Word/Excel/PPT 抽取文本后作答

## 三、架构设计

```
┌───────────────────────── 前端（Vue 3）─────────────────────────┐
│  职称管理 │ 人才账号 │ 补贴申领 │ 发放确认 │ 数据大屏 │ AI 助手  │
└────────────────────────────┬──────────────────────────────────┘
                             │  REST API (/api)
┌────────────────────────────┴──────────────────────────────────┐
│  路由层   auth / title / talent_account / subsidy / files      │
│           stats / export / report / import / ai_query          │
├───────────────────────────────────────────────────────────────┤
│  服务层   权限鉴权(JWT) · 字段加密 · 文件存储 · AI 桥接层       │
├───────────────────────────────────────────────────────────────┤
│  数据层   SQLAlchemy ORM + SQLite（可平滑切 PostgreSQL）       │
└───────────────────────────────────────────────────────────────┘
```

**部署形态**：单进程单端口。前端构建产物由 FastAPI 的 `StaticFiles` + SPA 兜底路由直接伺服，
生产环境**无需 Node.js 运行时**，一条 `uvicorn` 命令即可启动整套系统。

## 四、快速开始

### 环境要求
- Python 3.10+
- Node.js 18+（仅开发模式需要；生产部署可直接用已构建产物）

### 启动后端

```bash
cd backend
pip install -r requirements.txt

# 生成演示数据（会清空既有业务数据）
python seed_demo.py

# 启动服务
python -m uvicorn app.main:app --host 0.0.0.0 --port 8002
```

打开 http://localhost:8002 ，使用 **admin / admin123** 登录。

### 启动前端（开发模式）

```bash
cd frontend
npm install
npm run dev      # http://localhost:5175，已配置 /api 代理到 8002
```

生产构建：`npm run build` 会输出到 `backend/static/`，由后端直接伺服。

### 配置 AI（可选）

AI 能力默认关闭也能正常跑基础功能。如需启用，在 `backend/app/config.py` 中修改，或设置环境变量：

```bash
AI_ENABLED=true
AI_PROVIDER=local
AI_BASE_URL=http://your-llm-host:8000/v1    # 任意 OpenAI 兼容接口
AI_API_KEY=
AI_MODEL=your-model-name
```

## 五、关于演示数据

仓库内 `seed_demo.py` 生成的数据**全部为虚构数据**：

- 人员姓名、银行卡号、数币账号均由脚本随机生成
- 补贴金额、发放日期为演示用构造值
- 政策名称沿用各地**公开发布**的人才补贴政策（公开信息），仅用于还原真实业务场景

> 本仓库不包含任何真实业务数据、员工个人信息或企业内部文档。

## 六、技术亮点

**1. 字段级加密 + 列表脱敏**
敏感账号入库即 AES 加密，列表接口只返回脱敏掩码，明文需单独接口获取并记审计日志——避免"能看列表就能看全量账号"。

**2. AI 结果必须可人工订正**
大模型解析政策经常出错（适用对象缺失、月数识别错误）。系统设计为「AI 解析 → 人工确认 / 修改 → 生效」，
且人工改动后自动把政策打回待确认状态，防止错误规则被静默应用。

**3. NL2SQL 但绝不暴露 SQL**
AI 助手把自然语言转成 SQL 后执行，返回给用户的永远是**自然语言结论 + 中文表头表格**，
SQL 只存在于服务端日志，对非技术用户零门槛。

**4. 发放即重算，保证对账口径**
任何发放记录的增改删都会触发申领「累计到账」重算，避免 Excel 时代人工累加导致的对账偏差。

**5. 单进程部署**
FastAPI 同时伺服 API、上传文件与前端静态资源，配合 SPA 兜底路由，
内网一台机器一条命令即可交付使用，无需 Nginx / Node。

**6. 汇报材料自动化**
从数据库直接生成套用公司模板的 PPT（原生图表可二次编辑）、注册中文字体的 PDF、
以及可直接分享的 HTML，把每周/每月的汇报从"手工做表"变成"一键导出"。

## 八、说明

本项目为**学习与展示用途**的脱敏版本：

- 已移除所有真实业务数据、员工个人信息、企业内部文档与资产（如公司 PPT 模板）
- 代码中的内网地址、硬编码密钥、开发机路径均已替换为占位符
- 演示数据由 `seed_demo.py` 随机生成

如用于生产环境，请务必：
1. 通过环境变量设置 `SECRET_KEY`，不要使用默认值
2. 将 SQLite 切换为 PostgreSQL 等生产级数据库
3. 配置 HTTPS 与正式的备份策略
